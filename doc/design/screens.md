# 画面一覧

仕様書（[01_requirements.md](../spec/01_requirements.md)）のコア機能を実現するための画面。  
URL は設計時点の案。会員登録・ログインはスターターキットの既存画面を使う。

## Day4（講義中に作る範囲）

| 画面名 | URL | ログインが必要か | 使えるロール | 表示するもの・できること |
|-|-|-|-|-|
| 会員登録 | `/register` | 不要 | 誰でも | 名前・メール・パスワードの入力。「福祉施設として登録」を選べる（既存画面にロール選択を追加）。福祉施設を選んだときだけ事業所番号（10桁の数字、必須）と法人番号（13桁の数字、必須）の欄を出す |
| ログイン | `/login` | 不要 | 誰でも | ログイン、パスワードリセットへのリンク（既存画面のまま） |
| 慰問一覧 | `/` | 不要 | 誰でも | 公開中かつ開催前の慰問を開催日が近い順に表示。詳細へ進める。上部に慰問日記へのバナー |
| 慰問詳細 | `/visits/{visit}` | 不要 | 誰でも（下書きと非公開は福祉施設本人と管理者だけ。ほかは 404） | 日時、会場、説明、メニューごとの価格・残り人数・販売期間。メニューごとに人数（0〜10 と残り人数の小さいほう）を選び、「申し込み手続きへ進む」で選んだ人数をセッション（`purchase.{visit_id}`）に保存して申し込み内容の確認へ進む。販売期間外・売り切れのメニューは選べない |
| 申し込み内容の確認 | `/visits/{visit}/purchase` | 必要（未ログインならログイン後に戻る） | ログインユーザー | 選んだメニュー・人数・小計・合計。「支払いへ進む」で申し込み（pending）を作り、申し込み完了へ進む。売り切れ・販売期間外などはエラー表示。選んだ人数が無ければ慰問詳細へ戻す |
| 申し込み完了（仮） | `/entries/{entry}/complete` | 必要 | 申し込み者本人、その慰問の福祉施設、管理者 | 「申し込みを受け付けました」と表示するだけの仮画面。Stripe を入れるときに支払い完了の画面にする |
| ダッシュボード（振り分け） | `/dashboard` | 必要 | ログインユーザー | 画面は持たない。ロール別にリダイレクトする（管理者 → `/admin/visits`、福祉施設 → `/facility/visits`、慰問者 → `/entries`） |
| 福祉施設の慰問一覧 | `/facility/visits` | 必要 | 福祉施設 | 自分の慰問一覧（慰問名、開催日、下書き / 公開中 / 非公開の状態、編集ボタン）。新規登録・編集へ進める |
| 管理者の慰問一覧 | `/admin/visits` | 必要 | 管理者 | 全慰問の一覧（内容は未定。後の章で作る） |
| 慰問登録 | `/facility/visits/create` | 必要 | 福祉施設 | 慰問名、説明、会場、開始日時、終了日時を入力して下書きで保存。保存後は編集画面へ進む |
| 慰問編集 | `/facility/visits/{visit}/edit` | 必要 | 福祉施設（自分の慰問のみ） | 慰問の編集・削除、メニューの登録・編集・削除、下書き / 公開の切り替え。管理者が非公開にした慰問は切り替えできない（福祉施設には戻せない）。メニューは同じ画面の中で一覧と1つのフォーム（追加・編集で共用）で管理する。メニューが1つも無い慰問は公開できず、最後のメニューを削除できるのは下書きのときだけ（公開中と非公開では削除できない） |
| 申し込み確認 | `/entries/{entry}` | 必要 | ログインユーザー（自分の申し込みのみ） | 作成した申し込みの内容（メニュー、人数、合計金額）と状態。Day4 は「支払いへ進む」ボタンの手前まで |

## 平日課題

| 画面名 | URL | ログインが必要か | 使えるロール | 表示するもの・できること |
|-|-|-|-|-|
| Stripe Checkout（外部） | Stripe の URL | ─ | ログインユーザー | 申し込み確認の「支払いへ進む」から遷移し、カードで支払う。自作の画面ではない |
| 支払い完了 | `/entries/{entry}/complete` | 必要 | ログインユーザー（自分の申し込みのみ） | Day4 の仮画面を置き換える。`session_id` が申し込みの Checkout Session と一致し、申し込み者本人が開いたときだけ Stripe に支払い状況を問い合わせて確定する。paid なら「申し込みが完了しました」とマイページへのリンク、pending なら「確認中」を出し `wire:poll.3s` で再確認する。合計 0 円の申し込みは申し込み確認の時点で確定済み（開いたとき pending なら確定する）。Stripe のセッションが失効した、または確認が20回（約1分）を超えたときはポーリングをやめ、「支払いを確認できませんでした」とマイページへのリンクを出す |
| 支払いキャンセル | `/entries/{entry}/cancel` | 必要 | ログインユーザー（自分の申し込みのみ） | 支払いを中断した旨の表示、慰問詳細へ戻るリンク。開いただけでは何も変えない（GET で状態を変えない）。「申し込みを取り消す」を押すと、先に Stripe の決済ページを失効させ、成功したら `pending` の申し込みを `cancelled` にして枠を戻す。失効できなければ Stripe に状態を聞き、支払い済みなら確定、失効済みなら取り消し、不明なら取り消さずにエラーを出す。`paid` は変えない。申し込み者本人のみ（福祉施設・管理者は不可） |
| マイページ（申し込み一覧） | `/entries` | 必要 | ログインユーザー | 自分の申し込みの一覧（慰問名、日時、合計金額、状態）。キャンセルした申し込みは出さない。支払い待ちの行には「予約キャンセル」ボタンを出し、支払いキャンセルの画面と同じ手順（Stripe の決済ページを失効させてから `cancelled` にする）で取り消す。記録は削除しない |
| 申し込み詳細（参加証一覧） | `/entries/{entry}` | 必要 | ログインユーザー（自分の申し込みのみ） | Day4 の申し込み確認画面を拡張し、支払い済みなら発行された参加証を表示。当日に見せる画面 |
| 慰問の申し込み一覧と売上 | `/facility/visits/{visit}/entries` | 必要 | 福祉施設（自分の慰問のみ） | その慰問の申し込み一覧と売上合計 |

## 追加した画面

| 画面名 | URL | ログインが必要か | 使えるロール | 表示するもの・できること |
|-|-|-|-|-|
| 慰問日記 | `/diary` | 不要 | 誰でも | 慰問の様子を紹介する日記。いまは2件の記事（漫才・ダンスのイラスト、高齢者と出演者の感想、文章）を画面に直接書いている。慰問一覧の上部のバナーから進める |

## 画面ではないもの（平日課題）

| 名前 | URL | 内容 |
|-|-|-|
| Stripe Webhook | `POST /stripe/webhook` | 支払いを確定し、参加証を発行する |
| 申し込み完了メール | ─ | Webhook の処理の中で送る |
